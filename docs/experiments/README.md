# 실험: 장비 보고 신뢰(trust) vs 무게 실측 검증(verify)

## 목적

장비가 "명령을 수행했다"고 보고하는 것과 실제로 물리적 동작이 일어난 것은 별개다. `trust_device_report` 설정으로 두 판정 방식을 **같은 물리 조건에서** 비교해, 자기 보고를 판정 근거로 쓸 때 어떤 일이 벌어지는지 측정한다.

- **trust 모드** — 무게를 무시하고 장비의 `"done"` 응답 수신 여부만으로 판정
- **verify 모드** — 장비 응답과 무관하게, 명령 전후 무게 delta가 기대범위 안에 있어야 성공 판정

두 모드는 측정 시점과 측정 대상이 완전히 동일한 코드 경로를 탄다. 갈라지는 지점은 판정 한 줄뿐이며, 무게 delta는 두 모드 모두 항상 기록된다.

## 조건

| 항목 | 값 |
|---|---|
| 날짜 | 2026-08-27 |
| 장비 | `dispenser-01` (ESP32 + HX711 로드셀 + L9110 + 5V 워터펌프) |
| `duration_ms` | 3000 |
| 기대 delta 범위 | 40 ~ 110 g |
| 회차 | 모드별 20회, 순차 실행 |
| 실행 | `scripts/experiment.py` |
| 원본 데이터 | [`trust-vs-verify-20runs.csv`](./trust-vs-verify-20runs.csv) |

기대범위 40~110 g은 정상 상태에서 3000 ms 명령을 5회 반복 측정한 결과(평균 74.4 g, 표준편차 1.9 g)를 근거로 설정했다.

### 실패 주입

**L9110 모터 드라이버의 5V 전원 어댑터를 분리한 상태**에서 실행했다.

ESP32는 정상 동작하므로 명령을 수신하고 GPIO에 제어 신호를 출력한 뒤 `"done"`을 보고한다. 그러나 드라이버에 전원이 없어 펌프로 전류가 흐르지 않고 실제 토출은 일어나지 않는다. 재시도해도 결과는 동일한 통제된 실패 조건이다.

무인 매장에서 제어 보드는 살아 있으나 액추에이터 계통 전원이 차단된 상황을 재현한 것이다.

## 결과

| 모드 | N | pass | fail | 평균 delta (g) | 표준편차 (g) | 오판 |
|---|---|---|---|---|---|---|
| trust | 20 | 20 | 0 | 0.02 | 0.16 | **20** |
| verify | 20 | 0 | 20 | 0.02 | 0.13 | **0** |

오판 = `verdict=pass`인데 실제 delta가 기대범위 밖인 경우.

## 결론

두 모드의 평균 delta(0.02 g)와 표준편차(0.16 / 0.13 g)가 사실상 동일하다. **물리 조건이 완전히 같았다는 뜻이다.** 그럼에도 판정은 20/20 pass 대 0/20 pass로 완전히 갈렸다.

trust 모드는 20건 전부를 오판했다. 아무것도 토출되지 않았는데 전부 성공으로 기록됐다. verify 모드는 무게 실측만으로 20건 전부의 실패를 정확히 잡아냈다.

장비의 자체 보고를 성공 판정의 근거로 쓸 수 없다는 것을, 동일 조건 대조로 확인한 결과다.

## 재현

```bash
# 브로커와 서버 실행 후
python3 scripts/experiment.py --device-id dispenser-01 --duration-ms 3000 --runs-per-mode 20
```

verify 모드에서는 3회 연속 실패마다 HALT가 걸린다. 스크립트가 자동으로 resume 후 진행하므로 20회가 완주된다.
