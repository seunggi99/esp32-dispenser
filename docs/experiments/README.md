# 실험: 대조군(trust) vs 검증(verify) 모드 비교

## 목적

장비(ESP32)가 "명령을 수행했다"고 보고하는 것과, 실제로 물리적 동작이 일어난 것은
별개라는 것을 무게 실측으로 확인한다. `TRUST_DEVICE_REPORT` 설정으로 두 판정 방식을
같은 물리 조건에서 비교한다.

- **trust 모드**: 무게를 무시하고 장비의 "done" 보고만으로 성공 판정
- **verify 모드**: 장비 보고와 무관하게, 명령 전후 무게 delta가 기대범위(당시 설정: 30g~300g) 안에 있어야 성공 판정

## 실험 조건

- 파일: [`2026-08-27_power-cut-control.csv`](./2026-08-27_power-cut-control.csv)
- 날짜: 2026-08-27
- 장비: `dispenser-01` (ESP32 + HX711 로드셀 + L9110 모터 드라이버)
- `duration_ms`: 3000
- 모드별 20회씩, 순차 실행 (`scripts/experiment.py`)
- **통제된 실패 조건**: L9110 모터 드라이버의 5V 전원 어댑터를 의도적으로 분리한 상태에서 실행.
  ESP32 자체는 정상 동작 중이므로 명령을 수신하고 GPIO 제어 신호를 출력한 뒤 `"done"`을
  보고하지만, 드라이버에 전원이 없어 펌프에는 전류가 흐르지 않아 실제 토출은 발생하지 않는다.
  재시도해도 결과는 동일하다.
- 무인 매장에서 제어 보드는 살아있지만 액추에이터 계통 전원이 차단된 상황을 재현한 것.

## 결과

| 모드 | N | pass | fail | 평균 delta(g) | delta 표준편차(g) | 오판 |
|------|---|------|------|---------------|--------------------|------|
| trust | 20 | 20 | 0 | 0.02 | 0.16 | 20 |
| verify | 20 | 0 | 20 | 0.02 | 0.13 | 0 |

("오판" = `verdict=pass`인데 실제 delta가 기대범위(30g~300g) 밖인 경우)

## 결론

두 모드의 평균 delta(0.02g, 0.02g)와 표준편차(0.16g, 0.13g)가 사실상 동일하다는 것은
**물리적 조건이 완전히 같았음**을 보여준다. 그런데도 판정은 20/20 pass 대 0/20 pass로 완전히
갈렸다.

즉 trust 모드는 20건 전부를 오판(실제로는 아무것도 토출되지 않았는데 성공으로 기록)했고,
verify 모드는 무게 실측만으로 20건 전부의 실패를 정확히 잡아냈다. 장비의 자체 보고를
성공 판정의 근거로 쓸 수 없다는 것을 같은 물리 조건에서 직접 확인한 결과다.
