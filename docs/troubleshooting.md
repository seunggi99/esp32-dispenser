# 트러블슈팅

## OLED가 접촉 끊긴 후 복구되지 않음

**증상**

케이블이 흔들려 화면이 꺼지면, 접촉이 돌아와도 화면은 꺼진 상태로 유지됐다. 보드를 재부팅해야만 복구됐다.

**원인**

OLED 핀 헤더가 미납땜 상태로 배송되어 듀폰 케이블 압착으로 임시 고정한 상태였고, 접촉이 불안정했다.

SSD1306은 초기화 설정을 칩 내부 레지스터에 보관한다. 전원이 끊기면 설정이 소실되는데, `display.begin()`이 `setup()`에서 1회만 호출되므로 재설정 경로가 없었다.

**조치**

매 루프에서 `Wire.endTransmission()`으로 I2C 응답을 확인하고, 죽었다 살아난 경우 `display.begin()`을 재호출하도록 변경했다.

```cpp
bool alive = oledAlive();
if (alive && !oledOk) initOled();
else if (!alive) oledOk = false;
```

하드웨어 접촉 불안정을 소프트웨어 계층에서 흡수했다. 장치가 살아있는지를 스스로 보고하게 두지 않고 밖에서 확인한다는 점에서, 이 프로젝트의 판정 구조와 같은 형태다.

## 전원 인가 시 펌프가 의도치 않게 동작

**증상**

5V 어댑터를 콘센트에 꽂는 순간 펌프가 짧게 돌았다. ESP32가 아직 켜지지 않은 상태에서도 발생했다.

**원인**

ESP32는 USB로, L9110은 어댑터로 각각 전원을 받는 구조다. 어댑터를 먼저 연결하면 L9110만 살아 있고 제어 신호를 주는 ESP32는 꺼져 있는 구간이 생긴다. 이때 A-IA / A-IB 입력이 플로팅되어 L9110이 부정한 값을 HIGH로 읽었다.

ESP32 자체도 리셋 직후 `pinMode()` 실행 전까지 GPIO 상태가 확정되지 않는다.

**조치**

- `pinMode()` / `digitalWrite(LOW)` 를 `setup()` 최상단(`Serial.begin()` 이전)으로 이동
- 임시 운용 규칙: USB를 먼저 연결해 ESP32를 켠 뒤 어댑터를 연결

근본 대책은 A-IA / A-IB 각각과 GND 사이의 풀다운 저항이다. 소프트웨어만으로는 부트로더 실행 구간을 덮을 수 없다.

**의의**

제어기가 꺼져 있을 때 액추에이터는 정지 상태여야 한다. 이 프로젝트에서는 물이 조금 넘치는 정도지만, 실제 장비에서는 사고로 이어진다.

## MQTT result가 실제로는 왔는데 서버가 타임아웃 처리함

**증상**

장비는 정상적으로 펌프를 구동하고 result를 발행했는데(`mosquitto_sub`로 확인), 서버는 `result_timeout=true`로 기록하고 재시도를 걸었다.

**원인**

초기 구현에서 result 대기 시간과 무게 재측정 시점이 동일한 값(`duration_ms + stabilization_delay_s`)을 공유했다. MQTT 왕복 지연과 장비 처리 시간 때문에 result가 이 창을 벗어나 도착하는 경우가 있었다.

**조치**

result 대기(`result_wait_s`, 기본 10초)와 무게 재측정 시점을 분리해 `asyncio.gather`로 병렬 처리하도록 변경했다. 무게는 항상 정해진 시점에 재고, result는 그와 무관하게 `result_wait_s`까지 별도로 기다린 뒤 기록만 한다.

이 변경으로 장비가 응답하지 못한 경우에도 실제 실행 여부를 무게만으로 판정할 수 있게 됐다. 장비 응답이 판정에 개입하지 않는 구조가 여기서 완성됐다.

## 안정화 대기 부족으로 오판정

**증상**

정상 동작인데도 판정이 실패하고 재시도가 걸려, 한 명령에 펌프가 2~3회 돌았다.

**원인**

`stabilization_delay_s`가 1.5초였다. 텔레메트리를 보면 물이 컵에 떨어진 뒤 무게가 안정되기까지 3~4초가 걸리는데, 그 전에 측정해 과도 상태의 값을 읽고 있었다.

**조치**

`stabilization_delay_s`를 4.0초로 조정. 이후 5회 연속 측정에서 `retry_count=0`, 편차 ±2 g로 안정화됐다.
